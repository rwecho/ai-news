最近刷到一条视频，文案写得很直接：

> 数字人不稀奇。  
> 可互动的数字人也不稀奇。  
> 那如果是带深夜福利、可互动的数字人呢？

视频里展示的是一个叫“小岚”的互动网页。

<DriveVideo fileId="1mWEpU9rv_zIY3Se0Gpl5U6t2IGPBRZj4" title="小岚互动数字人原始视频" />

原始视频已经归档到 Google Drive，文章通过 Drive 文件播放；X 链接仅作为原始来源和出处。

左边是一个女性数字人，右边是聊天和控制面板。用户可以让她回应、切换模式，还能改变服装和动作。

看起来像是一个非常复杂的实时数字人系统。

但我把视频逐帧看了一遍，感觉它真正聪明的地方，可能不在数字人本身，而在产品包装。

## 它可能不是实时生成，而是状态切换

视频里的人物、房间、光线和镜头都非常稳定。

当用户点击不同按钮后，人物会换衣服、改变姿势，但背景和镜头几乎没有变化。整个切换过程也非常干净，没有明显的生成等待。

所以更合理的推测是：

```text
用户点击按钮
→ 前端切换数字人状态
→ 播放对应图片或短视频
→ 同时更新文字和语音
```

也就是说，它可能提前准备了很多状态：

```text
普通状态
睡衣状态
夜间状态
微笑状态
挥手状态
说话状态
换装状态
```

用户看到的是一个“会回应的人”，但背后很可能是一个设计得很好的状态机。

这并不是贬低。

相反，这种方式比每次都调用视频生成模型更稳定，也更适合真正做成产品。

## 一套完整的数字人系统，至少有五层

### 第一层：人物素材

先固定一个角色。

需要固定：

- 脸型
- 发型
- 年龄设定
- 服装风格
- 房间背景
- 镜头位置
- 光线和色调

如果每次生成的人物都不一样，用户不会觉得这是同一个数字人，只会觉得网页换了几张图。

建议先制作一张人物参考图，再生成：

```text
idle
smile
wave
thinking
speaking
sleepwear
night-mode
```

这些素材可以用图片生成模型制作，也可以用真人拍摄后再做数字人处理。

但如果使用真人脸，必须获得本人授权。不能拿别人的照片直接做成人化或暧昧化数字人。

### 第二层：动作和短视频

最简单的做法不是实时生成，而是提前制作短视频。

例如：

```text
idle.mp4
smile.mp4
wave.mp4
speak-01.mp4
speak-02.mp4
change-clothes-01.mp4
change-clothes-02.mp4
```

每个视频只需要几秒钟。

用户点击“让她笑一下”，网页就播放 `smile.mp4`。

用户点击“夜间模式”，网页就播放另一段视频。

这种方式有几个好处：

- 没有实时生成等待
- 不依赖 GPU
- 画面更稳定
- 成本低
- 适合快速做出 Demo

### 第三层：对话模型

如果用户可以自由输入文字，就需要接一个大语言模型。

模型不负责生成画面，只负责生成回复：

```text
用户：你今天看起来不错。

模型：今天心情还不错，你呢？
```

系统可以让模型返回：

```json
{
  "text": "今天心情还不错，你呢？",
  "emotion": "smile",
  "action": "wave"
}
```

前端根据 `emotion` 和 `action` 播放对应的视频。

角色提示词可以这样写：

```text
你是“小岚”，一个明确为成年人的虚拟角色。

你的语气自然、简短、有一点调侃，但不要像客服，也不要频繁使用“亲爱的”“宝宝”等称呼。

你可以表达开心、疑惑、害羞和拒绝，但不要假装自己是真人。
遇到越界、违法、未成年人或非自愿内容时，直接拒绝。

每次回复尽量控制在两句话以内。
同时返回 emotion 和 action 字段。
```

### 第四层：语音

模型生成文字之后，再调用 TTS 生成语音。

流程是：

```text
文字回复
→ TTS 生成语音
→ 播放语音
→ 播放对应的数字人视频
```

第一版不需要追求实时口型。

可以先录制几十个高频回复：

```text
你好
你来了
我刚刚在等你
今天怎么样
你想聊什么
我不回答这个问题
```

等产品跑通之后，再接实时语音和口型同步。

### 第五层：前端状态机

前端可以用 Next.js 或 React。

```ts
const avatarStates = {
  idle: {
    video: "drive-file-id-001",
    text: "你来了。"
  },
  smile: {
    video: "drive-file-id-002",
    text: "看到你，我心情不错。"
  },
  night: {
    video: "drive-file-id-003",
    text: "现在已经是夜间模式了。"
  }
};
```

用户点击按钮：

```ts
function changeState(nextState: string) {
  setCurrentState(nextState);

  const state = avatarStates[nextState];

  playVideo(state.video);
  showText(state.text);
}
```

这就是它的核心：

```text
动作不是临时生成的
动作是提前准备好的
聊天只是决定下一步播放哪个状态
```

## 如果需要真正实时的数字人怎么办？

如果希望用户输入任何内容，数字人都能即时说话和做表情，可以接音频驱动的人像动画模型。

- [LivePortrait](https://github.com/KwaiVGI/LivePortrait)：用驱动动作控制人像的表情和头部运动。
- [EchoMimic](https://badtobest.github.io/EchoMimic/)：支持通过音频和面部动作生成肖像动画。
- [DH_live](https://github.com/kleinlee/DH_live/)：偏向轻量级 2D 视频数字人和网页实时运行。

但这条路线的难点也很明显：

- 长时间运行容易出现脸部漂移
- 全身动作比头像难很多
- 服装切换不容易保持一致
- 需要 GPU
- 多用户同时使用时成本会上升

所以第一版不应该从“实时全身数字人”开始。

## “深夜模式”应该怎么设计？

从技术上说，它只是一个状态：

```text
普通模式
→ 夜间模式
→ 特定服装或场景
→ 对应的语音和动作
```

但产品必须设置边界：

- 明确角色是成年人
- 设置年龄确认
- 不使用未成年人形象
- 不使用真人未经授权的脸
- 不允许用户把他人的照片成人化
- 不生成非自愿或违法内容
- 提供举报和退出机制

最稳妥的方案是固定素材，而不是让模型自由生成。

这样既能控制画面质量，也能控制版权和安全风险。

## Google Drive 怎么保存素材？

可以这样设计：

```text
小岚互动数字人/
├── 00_人物参考图/
├── 01_普通状态/
├── 02_动作视频/
├── 03_服装状态/
├── 04_语音文件/
├── 05_网页预览素材/
├── 06_版权与授权/
└── manifest.json
```

GitHub 只保存：

```json
{
  "character": "xiaolan",
  "states": {
    "idle": {
      "driveFileId": "xxx"
    },
    "smile": {
      "driveFileId": "yyy"
    }
  }
}
```

视频和图片全部放 Google Drive，GitHub 只保存文件 ID、状态名称和展示规则。

不过需要注意，Google Drive 更适合素材管理和低流量预览，不适合直接承担高并发视频分发。以后如果访问量起来，可以保留 Drive 作为原始素材库，再增加 CDN 或对象存储作为播放层。

## 我们真正应该怎么做？

我建议先做一个最小版本：

```text
Next.js
+ 1 个固定数字人
+ 1 个房间场景
+ 5 个状态
+ 8 个动作视频
+ 20 条预设语音
+ 一个聊天窗口
+ Google Drive 素材库
+ 年龄和内容安全控制
```

先不要一开始就训练模型，也不要急着做复杂的实时渲染。

这个产品最有价值的地方，不是“数字人有多逼真”，而是：

> 用户点击一下，她真的会回应。  
> 用户说一句话，她的状态会发生变化。  
> 用户会觉得自己不是在看一段视频，而是在和一个角色互动。

这才是视频里真正值得学习的地方。
